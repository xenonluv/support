## 0. 검토자에게 요청하는 사항
1. 단계 순서와 나눈 방식이 적절한가. 특히 배포와 마이크 테스트를 DB보다 앞에 둔 순서
2. **무료 우선** 구성에 빠진 비용이나 무료 한도 위험이 있는가
3. 각 단계의 완료 기준이 실제로 확인 가능한가
4. 개인정보 원칙(음성 미저장, 성명 미저장, 마스킹)이 단계별 작업에 빠짐없이 반영됐는가
5. 데이터 모델이 화면 시안의 지표(요약 카드, 정렬 기준)를 계산할 수 있는가
6. 12장 "결정 필요" 항목에 대한 의견

## 1. 서비스 요약
- **돌봄이음** (dolbomieum.kr): 광주 통합돌봄 현장 인력이 방문 직후 30초 동안 구술하면 AI가 세 가지 초안을 만든다.
  - ① 규격 돌봄기록 초안 ② 이상징후 플래그와 알림 문안 ③ 기관 간 인수인계 브리핑
- 사용자는 두 부류다: 현장 돌봄인력(모바일), 동 담당자·기관 관리자(PC 대시보드)
- 원칙
  - AI 결과는 모두 "초안"이며 사람이 확인한 뒤 복사해서 쓴다. AI는 판정하지 않는다.
  - 음성 원본과 성명·주소·연락처는 저장하지 않는다.
- 성과지표: 작성시간 50% 단축, 파일럿 5~10명이 2주 사용, 기록 200건 이상, 수용률 80% 이상

**LLM 절감책**
- 모델명은 `lib/ai/models.ts` 한 곳에서 상수로 관리한다.
  - 개발·반복 테스트: `claude-haiku-5-5`
  - 시연·파일럿: `claude-sonnet-5-5`
  - 환경변수로 전환한다.
- 단위 테스트는 실제 API를 호출하지 않는다. 저장한 응답 fixture로 파싱과 검증만 테스트한다.
- 시스템 프롬프트(서식 정의, 징후 정의)에 프롬프트 캐싱을 적용한다.
- Anthropic 콘솔에서 월 사용 한도를 설정한다(사용자 작업).
- 무료 LLM(Gemini 무료 티어 등)은 쓰지 않는다. 입력 데이터가 학습에 쓰일 수 있어 개인정보 원칙과 충돌한다.

**예산서와 다른 점:** 세부계획서 예산은 STT 40만원, 호스팅 35만원이다. 실제 구성은 0원이다. 남는 금액을 변경 신청할지는 사용자가 판단한다.

## 5. 단계별 상세

### 0단계 — 계정·키 준비 (사용자 작업)
- Vercel(GitHub 로그인), Supabase(새 프로젝트, Seoul `ap-northeast-2`), Groq, Anthropic에 가입한다.
- Cloudflare에 `dolbomieum.kr`을 추가하고, 안내받은 네임서버 2개를 가비아에 입력한다. 반영까지 최대 1일 걸린다.
- Anthropic 월 사용 한도를 설정한다.
- **결과물:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GROQ_API_KEY`, `ANTHROPIC_API_KEY`
- Claude는 키가 필요한 지점에서 멈추고 사용자에게 요청한다. 키 없이 할 수 있는 1·2단계는 먼저 진행한다.

### 1단계 — 프로젝트 뼈대
**작업**
- `npx create-next-app@latest web --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"`
- `npx shadcn@latest init`
- 의존성: `@supabase/supabase-js @supabase/ssr @anthropic-ai/sdk groq-sdk zod`, 개발용 `vitest prettier supabase @types/node@24`
  - `@vitejs/plugin-react`는 2026-10-10 기준 peer 의존성 충돌로 제외함. 1단계 테스트는 JSX가 필요 없음. 컴포넌트 테스트가 필요해지면 다시 검토.
- 스크립트: `dev`, `build`, `lint`, `typecheck`(`next typegen && tsc --noEmit`), `test`(`vitest run`), `format`(`prettier --write .`)
  - `next typegen`은 `LayoutProps` 등 라우트 타입을 만든다. 없으면 처음 받은 저장소에서 tsc가 실패한다.
- `engines.node`와 `web/.nvmrc`로 Node LTS 버전을 고정한다.
- `.env.example`은 커밋하고 `.env.local`은 git에서 제외한다.
- `src/` 아래 폴더 골격: `app/(auth)`, `app/(worker)`, `app/(manager)`, `app/api`, `lib/{stt,ai,privacy,supabase,audio}`, `schemas`, `components`
- 루트 `CLAUDE.md`에 넣을 내용
  - 공통 모듈 규칙
    - STT는 `lib/stt`의 `transcribe()`만 쓴다.
    - LLM은 `lib/ai`만 쓴다.
    - 타입은 `schemas/`의 Zod 스키마와 Supabase 생성 타입만 쓴다.
  - 개인정보 규칙
  - 검증 명령
  - 현재 단계
  - 커밋 규칙
- `set-bypass-mode.bat/.ps1`(Windows 전용) 삭제 여부를 사용자에게 확인한다.

**완료 기준**
- 검증 명령 3개 통과
- `npm run build` 성공
- 로컬 `npm run dev` 첫 화면 표시

### 2단계 — 디자인 기반 (`doc/design_ui.png` 기준)
**시안에서 읽은 구성**
- 왼쪽 남색 사이드바
  - 로고, 기관 선택 드롭다운
  - 업무 메뉴: 오늘의 방문 / 기록 작성 / 인수인계 브리핑 / 이상징후 현황(미확인 배지)
  - 관리 메뉴: 대상자 목록(수) / 연계 기관(수) / 설정
  - 하단: 사용자 소속·담당, 로그아웃
- 상단: 브레드크럼과 한 줄 요약("오늘 128명 중 먼저 볼 3명")
- 요약 카드 4개(작은 추이 그래프 포함): 주의 필요 / 관찰 지속 / 특이사항 없음 / 이번 달 조기 발견(진한 남색 카드)
- "먼저 확인할 어르신" 목록
  - 각 행: 순위 배지, 대상자, 신호 요약(핵심어는 빨강 강조), 상태 배지, "N개 기관", [브리핑] 버튼
- 모바일 알림 상세
  - "확인이 필요해요" 헤더, 신호 겹침 경고 박스
  - 신호 카드(지속 일수·신규 배지)
  - 연계 알림 문안과 [수정]·[전송하기] 버튼
- 하단 원칙 문구: "AI는 판정하지 않고, 담당자에게 확인을 요청합니다"

- 공통 컴포넌트: `AppSidebar`, `StatusBadge`(주의/관찰/해소/신규), `StatCard`(스파크라인), `ClientRankRow`, `SignalCard`, `CopyButton`, `AiNotice`(원칙 문구)
- 스파크라인은 의존성을 늘리지 않도록 인라인 SVG로 직접 그린다(검토 요청: 차트 라이브러리 필요 여부).
- 현장 인력용 모바일 화면은 시안에 없다. 같은 토큰으로 새로 설계하며, 큰 녹음 버튼과 한 손 조작을 기준으로 한다.
- 시안과 다르게 구현하는 부분
  - "이음기록" → **"돌봄이음"**
  - "김○○·78세·서구 화정○동" → **식별번호 + 연령대 + 동**
  - [전송하기] → **[복사]** (실제 발송은 사람이 기존 채널로 한다)
  - [사례회의 소집]은 MVP에서 제외

**완료 기준**

**결정 (2026-10-10)**

- 실행 계획: `doc/plans/2026-10-10-2단계-디자인-기반.md`

### 3단계 — 배포·도메인
**작업**
- GitHub 푸시 후 Vercel에서 import한다. **Root Directory = `web`**
- Vercel 환경변수를 입력한다.
- Domains에 `dolbomieum.kr`과 `www`를 추가한다.
- Cloudflare DNS에 Vercel 화면이 안내하는 레코드를 입력한다. 프록시는 끈다.

**순서 이유:** 마이크 권한은 HTTPS에서만 동작한다. 실기기 테스트를 일찍 하려면 배포가 먼저 필요하다.

**완료 기준**
- `https://dolbomieum.kr` 접속, SSL 정상
- push하면 자동 배포됨

**완료 (2026-10-10)**
- Vercel 프로젝트 `support`(팀 `mrpyo-s-projects`, Root Directory `web`, Node 24.x), 기본 주소 `https://support-rosy-gamma.vercel.app`
- Cloudflare 네임서버: `paityn.ns.cloudflare.com`, `javon.ns.cloudflare.com` (가비아에서 변경)
- DNS(Cloudflare, 모두 DNS only 회색 구름): `@`와 `www` 둘 다 CNAME → `ce26318cb9873fa8.vercel-dns-017.com` (루트는 Cloudflare CNAME flattening으로 Vercel IP 응답). Vercel의 Domain Connect 링크로 자동 입력함
  - 참고: 예전 안내의 `A 76.76.21.21`, `cname.vercel-dns.com`은 Vercel의 2순위 권장값이 됨
- `www.dolbomieum.kr`와 `http://` → `https://dolbomieum.kr` 308 이동
- SSL: Let's Encrypt 자동 발급(2026-10-10 ~ 2027-01-08, Vercel이 자동 갱신)
- 확인: 6개 화면 200, 없는 대상자 주소는 한국어 404
- 환경변수는 아직 없음(5·6단계에서 Supabase·Groq·Anthropic 키 추가)
- 도메인 관리는 Vercel CLI로 가능: `vercel domains verify dolbomieum.kr --scope mrpyo-s-projects` (Vercel 새 대시보드는 Settings 메뉴에 Domains 항목이 보이지 않음)

### 4단계 — 마이크 스모크 테스트
**작업** (`구현1.md` 9-1장)

- 결과는 `구현1.md` 9-1 표에 반영한다.

|---|---|
| `agencies` | id, name, type(동센터/수행기관/복지관) |
| `workers` | id(=auth.users.id), agency_id, role(worker/manager), display_name |
| `clients` | id, code(식별번호), age_band(연령대), dong(동), created_at — **성명·주소·연락처 컬럼 없음** |
| `client_agencies` | client_id, agency_id (구현1.md의 `agency_ids[]` 대신 조인 테이블 사용 → 구현1.md도 갱신) |
| `visit_records` | id, client_id, worker_id, agency_id, visited_at, transcript_text, draft_json, final_json, edited, edit_ratio, input_mode, stt_engine, duration_ms, created_at |
| `flags` | id, record_id, client_id, type, level(관찰/주의), evidence_quote, status(미확인/확인/조치/해소), first_seen_at, resolved_by, resolved_at, outcome(연계됨 등) |
| `alert_drafts` | id, flag_id, target, body, copied_at |
| `briefings` | id, client_id, period_from, period_to, body, created_by |

- `clients.age_band`, `dong`과 `flags.first_seen_at`, `outcome`은 시안의 표시와 지표 때문에 구현1.md보다 추가한 컬럼이다(검토 요청).
  - 표시: 연령대·동, 지속 일수
  - 지표: "이번 달 조기 발견"

**RLS**
- worker: 자기 기관과 `client_agencies`로 연결된 대상자와 그 기록만 볼 수 있다. 쓰기는 본인 기록만 가능하다.
- manager: 자기 기관에 연결된 대상자 전체를 볼 수 있다(기관을 넘나드는 브리핑은 같은 대상자를 공유하는 범위에서만).
- `service_role` 키는 서버 전용 관리 작업에만 쓴다.

**인증**
- Supabase Auth 이메일+비밀번호를 쓰고, 관리자가 계정을 직접 만든다.
- `@supabase/ssr` 미들웨어로 세션을 유지한다.
- 로그인 후 role에 따라 `(worker)`/`(manager)`로 리다이렉트한다.

**기타**
- 시드 데이터: 테스트 기관 2개, worker·manager 계정, 대상자 몇 명
- 타입 생성: `supabase gen types typescript` → `lib/supabase/types.ts`

**완료 기준**
- 역할별로 화면이 갈린다.
- **worker A 계정으로 기관 B 전용 대상자를 조회하면 0건**이 나오는 RLS 테스트(SQL 또는 통합 테스트)

### 6단계 — 기능① 음성 → 기록 초안
**선행 작업:** 「2026년 노인맞춤돌봄서비스 사업안내」에서 기록 항목을 확정한다. 원문 분석은 사용자 자료가 필요하다.

**작업**
- `schemas/record.ts`: 기록 초안 Zod 스키마를 정의한다. 단일 출처이며, Claude 구조화 출력용 JSON 스키마도 여기서 만든다.
- `lib/privacy/mask.ts`: 성명·전화번호·주소·주민번호 패턴을 마스킹한다. TDD로 만들며 한국어 케이스를 충분히 넣는다.
- `lib/stt`
  - `transcribe(audio, opts)` 인터페이스와 Groq 구현(`language: "ko"`, 돌봄 용어 prompt)
  - 엔진을 교체할 수 있는 구조로 만든다.
- `app/api/transcribe/route.ts`
  - 음성은 메모리에서만 처리한다. 파일·스토리지·로그에 남기지 않는다.
  - 크기와 길이 제한, 인증 확인
- `lib/ai`: Claude 호출, 시스템 프롬프트(서식 정의, "추측 금지·빈 값 허용"), 프롬프트 캐싱, 모델 상수
- `app/api/draft/route.ts`: 마스킹 → Claude 호출 → 스트리밍 응답 → 스키마 검증
- 화면 `(worker)/record`
  - 대상자 선택, 녹음 버튼, 실시간 글자(지원 기기만), 초안 편집, [저장]·[복사]
  - 텍스트 입력 전환 버튼
- 저장 시 `edit_ratio`(초안과 최종본의 편집 거리 비율)와 `duration_ms`(녹음 시작~저장)를 기록한다.
- `(worker)/visits`, `(worker)/my-records` 기본 화면

**완료 기준**
- 실기기에서 30초 녹음 → 초안 표시 → 저장까지 된다. 지연 시간을 실측한다.
- Groq 키를 일부러 망가뜨려도 Web Speech 또는 텍스트 입력으로 기록할 수 있다.
- DB, Vercel 로그, Supabase 스토리지에 음성 파일과 원문 성명이 없다.

### 7단계 — 기능③ 이상징후·대시보드 (중간발표)
**작업**
- `schemas/flag.ts`
  - 5종: 약 미복용, 식사량 감소, 낙상, 정서적 위축, 방문 거부
  - 수준: 관찰/주의
  - 근거 문장 인용은 필수
- 6단계 초안 생성 응답에 플래그와 알림 문안을 함께 포함한다. 호출을 한 번으로 줄여 비용을 아낀다.
- 같은 대상자의 기존 플래그와 합쳐 지속 일수와 "신규" 여부를 계산한다.
- `(manager)/signals`
  - 한 줄 요약, 요약 카드 4개, "먼저 확인할 어르신" 목록
  - 정렬: 신호 수 → 지속 기간 → 관찰 기관 수
  - 기간 필터
- 알림 상세(모바일 대응)
  - 신호 겹침 경고, 신호 카드, 알림 문안 [수정]·[복사]
  - 복사하면 `copied_at`을 기록한다.
- 플래그 상태 변경: 확인/조치/해소, outcome

**완료 기준**
- 샘플 구술 10~20건(fixture)으로 5종 탐지를 수동 점검한다. 오탐·누락 목록을 기록한다.
- 대시보드 수치가 DB 집계와 일치한다.

### 8단계 — 기능② 인수인계 브리핑

# 현장 인력 "대상자 상황" 화면 (함께 보기) 실행 계획

## 답변 요약
- **취지:** 함께 보는 쪽이 맞습니다.
  - 서비스 한 줄 정의(`doc/구현1.md`)의 핵심이 "기관 간 인수인계"입니다.
  - DB 권한도 처음부터 그렇게 설계했습니다.
    - 정책 주석: "볼 수 있는 대상자의 기록은 조회(인수인계), 쓰기는 본인 기록만".
    - 현장 인력은 지금도 함께 맡은 대상자에 대해 다른 기관의 기록과 신호를 읽을 수 있습니다. 화면만 없습니다.
- **난이도:** 쉬움~보통이고 1.5~2시간 걸립니다.
  - DB는 바꾸지 않고(마이그레이션 없음) AI도 호출하지 않아서 추가 비용이 없습니다.

## Context
- 지금 현장 인력은 기록만 하고 상황을 볼 수 없습니다.
  - "오늘의 방문"의 '마지막 기록'은 내 기록만 기준으로 합니다.
  - "내 기록"도 내 것만 보여 줍니다.
  - 신호와 다른 사람의 기록은 관리자 화면에만 있습니다.
- 결과물
  - 현장 인력이 방문 전에 그 어르신의 아직 해결 안 된 이상징후와 최근 기록(모든 연결 기관)을 읽기 전용으로 봅니다.
  - 신호 확인과 해소 처리는 지금처럼 관리자만 합니다(RLS `flags_update`가 manager만 허용).

## 제가 정한 결정
1. **작성자는 기관 이름으로만 표시하고, 내 기록에는 "내 기록" 배지를 붙입니다.**
   - 동료 이름은 RLS(`workers_select`: 본인만)상 보이지 않고, 굳이 열지 않습니다.
2. **다른 사람 기록에는 복사 버튼을 두지 않습니다.** 펼쳐 읽기만 합니다. 복사는 지금처럼 "내 기록"에서 합니다.
3. **AI 브리핑은 넣지 않습니다.** 원래 기록만 보여 주므로 비용이 없습니다.
4. **상세 화면 주소는 내부 id를 씁니다** (`/visits/[clientId]`). 식별번호가 바뀌어도 링크가 유지됩니다. 관리자 `/clients/[clientId]`와 같은 방식입니다.
5. **목록 순서는 지금처럼 번호순입니다.** 신호는 카드 배지로 표시합니다.
   - 마지막 방문은 누가 다녀왔든 가장 최근 날짜로 바꿉니다.

## 작업

### 1. 데이터 (`src/lib/visits/`, 새 폴더)
- `build.ts` (순수 함수)
  - `buildVisitCards(clients, visits, flags, userId)`
  - 대상자별 결과
    - 가장 최근 방문일(누구든)과, 그 방문이 내 것인지
    - 미해결 신호 종류 수
    - 주의 등급 포함 여부
- `data.ts` (세션을 읽으므로 `connection()`을 쓰고 Suspense 안에서만 부릅니다)
  - `getVisitCards()`
    - 종결 안 된 대상자를 읽습니다.
    - 방문 기록 `client_id, visited_at, worker_id`는 `readAll`(`src/lib/metrics/rows.ts`)로 끝까지 읽습니다.
    - `flags`에서 `status != resolved`인 `client_id, type, level`을 읽습니다.
    - 그 결과를 `buildVisitCards`에 넘깁니다.
  - `getClientStatus(clientId)`
    - uuid 형식을 검사합니다(`clients/data.ts`의 getClientEdit 패턴).
    - 대상자를 읽습니다: `closed_at` 포함, RLS 적용, 못 보면 null.
    - 최근 기록 20건을 읽습니다: `visit_records`의 `id, visited_at, worker_id, final_json, agencies(name)`. `RecordDraftSchema.safeParse`를 거칩니다(`briefing/data.ts`의 `loadBriefingSource` 패턴).
    - 미해결 신호는 기존 `loadClientSignals`(`src/lib/dashboard/data.ts`)를 다시 쓰고 resolved를 뺍니다.
- `src/lib/records/data.ts`의 `getMyClients`: 이제 기록 화면만 쓰므로 `lastVisitedAt`와 방문 조회를 뺍니다(쿼리 1개 감소).

### 2. 화면
- `src/app/(worker)/visits/page.tsx` 카드
  - 내용
    - "최근 방문 10/9 (내 기록)" 또는 "최근 방문 10/9", 기록이 없으면 "기록 없음"
    - 신호가 있으면 `ToneBadge`로 "확인 필요 N"을 붙입니다(주의는 caution, 관찰만 있으면 observe).
  - 버튼: [상황 보기](outline) [기록하기](기존)
- `src/app/(worker)/visits/[clientId]/page.tsx` (새 파일, `signals/[clientId]` 구조를 따릅니다)
  - 위에서부터
    - "← 오늘의 방문" 링크
    - 대상자 표시(`clientLabel`)
    - **아직 해결 안 된 이상징후**: 읽기 전용 카드 목록. 아래에 "확인·해소는 동 담당자가 처리해요"와 `AiNotice`를 둡니다.
    - **최근 기록 (모든 기관)**: 날짜·기관명, "내 기록" 배지, 요약, "전체 보기" 펼침(`formatRecordText`)
  - 맨 아래 [기록하기] 버튼(`/record?client=번호`)
    - 종결된 대상자면 버튼 대신 "종결된 대상자예요"를 보여 줍니다.
  - 못 보는 대상자이거나 잘못된 id면 `notFound()`
- `src/components/signal-status-card.tsx`
  - 제목·배지·근거·기관 수 부분을 `SignalSummary`(표시 전용 컴포넌트)로 떼어 냅니다.
  - 관리자 카드와 현장 화면이 함께 씁니다(중복 방지). 관리자 화면 동작은 그대로입니다.
- 경로 권한은 바꾸지 않아도 됩니다. `/visits/*`는 이미 `WORKER_ONLY`에 속합니다(`src/lib/auth/routes.ts`의 `under`).

## 검증
1. `npm run typecheck && npm run lint && npm test`, `npm run build`
2. `npm run test:rls`: 기존 40개와 새 검사가 모두 통과해야 합니다.
3. 로컬 e2e(헤드리스 크롬, 시험 계정)
   1. 현장 B가 C-0012에 기록을 남깁니다.
   2. 현장 A의 "오늘의 방문" C-0012 카드에 최근 방문 날짜가 바뀌어 보입니다.
   3. [상황 보기]에 B 기관 기록(기관명 표시, 복사 버튼 없음)과 미해결 신호(처리 버튼 없음)가 보입니다.
   4. 관리자가 `/visits/<id>`로 가면 홈으로 돌아갑니다.
   5. 남이 볼 수 없는 id로 열면 404입니다.
4. 점검에서 만든 기록은 비밀 키로 지웁니다. 파일럿 데이터는 건드리지 않습니다.
5. 커밋·푸시는 사용자가 요청할 때만 합니다.

# 9단계 파일럿·성과 측정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** 현장 파일럿(5~10명, 2주)을 바로 시작할 수 있게 준비한다. 성과지표 4개를 화면과 스크립트로 계산한다.
- 준비물: 계정 일괄 발급, 사용 안내 1장, 백업
- 성과지표 4개: 작성시간 50% 단축, 5~10명·2주 사용, 누적 기록 200건, 수용률 80%

**Spec:** `doc/단계개발.md` 5장 "9단계", `doc/구현1.md` 성과지표(27행)·지표 산출(107행)

## 범위
- 9-1 준비(이번 작업, 코드): 아래 Tasks
- 9-2 운영(사용자): 참여자 모집, 2주 사용, 사전조사의 기존 작성시간 제공
  - 끝나면 `npm run metrics`로 최종 지표를 낸다.

## 결정 (2026-10-11)
- 파일럿 데이터 구분: `workers.pilot`(기본 false)을 추가한다. 파일럿 계정 스크립트만 true로 만든다.
  - 지표는 파일럿 참여자의 기록만 센다. 시험 계정·시연 데이터(`stt_engine='seed-demo'`)는 빠진다.
- 수용률
  - AI 초안이 있는 기록만 센다. "AI 없이 직접 작성"은 초안이 비어 있어 수정 비율이 의미가 없으므로 뺀다.
  - 수정 비율 0 = 그대로, 0 초과 0.2 이하 = 경미 수정, 0.2 초과 = 많이 수정
  - 수용률 = (그대로 + 경미 수정) ÷ AI 초안 기록
  - 경미 수정 기준 0.2(글자 20%)는 "결정 필요 4"에 대한 결정이다.
- 작성시간
  - `duration_ms`(녹음·입력 시작 → 저장)의 평균을 쓴다. 30분을 넘는 기록은 화면을 열어 둔 경우로 보고 평균에서 빼고, 뺀 건수를 함께 보인다. 중앙값도 보인다.
  - 단축률 = 1 − 평균 ÷ 기존 작성시간
  - 기존 작성시간(사전조사 값)은 사용자에게 받는다. 받기 전에는 "기존 작성시간 미입력"으로 보인다(`lib/metrics/targets.ts`의 `BASELINE_MINUTES`).
- 사용 인원·기간: 기록을 1건 이상 남긴 파일럿 참여자 수, 첫 기록일~마지막 기록일(서울)
- 화면 `/metrics`(관리자): 내 기관 파일럿 참여자 기준 지표 4개와 목표 달성 여부, 수용률·작성시간 내역
- 스크립트 `npm run metrics`: 모든 기관 파일럿 참여자 기준. 최종 보고용이다.
- 계정 발급 `npm run pilot:accounts -- pilot/pilot.json`
  - 설정 파일(기관·대상자 식별번호·참여자 이메일)과 결과 파일(임시 비밀번호)은 개인정보라 git에 넣지 않는다(`web/pilot/`, 예시 파일만 커밋).
  - 대상자는 식별번호·연령대·동만 받는다.
  - 다시 실행해도 안전하다: 있는 계정은 비밀번호를 그대로 둔다. 바꾸려면 `--reset-passwords`
- 사용 안내 `/guide`: 로그인 전에도 볼 수 있고 A4 1장으로 인쇄된다.
  - 접속·로그인, 홈 화면 추가(안드로이드·아이폰), 마이크 권한, 말하는 요령(이름 대신 식별번호), 초안 확인·신호 빼기, 카카오톡 인앱 브라우저
  - 현장 화면 머리말에서 링크한다.
- 마이크 권한 거부 안내에 `/mic-test` 링크를 단다.
- 백업 `npm run backup`: 관리 키로 public 테이블을 JSON으로 내보낸다(`web/backups/`, git 제외).
  - Docker가 꺼져 있어 `supabase db dump`는 쓰지 않는다.
- 로그 점검: 운영에서 표식 글자가 든 구술로 초안을 만든 뒤, Vercel 로그에 그 글자가 없는지 확인한다.
- 마지막 검토: 보안 리뷰 1회(크리티컬만 수정)

## Review Focus
- 기록 0건(파일럿 시작 전) → 지표 화면이 0으로 나누지 않고 "아직 기록이 없어요"
- 직접 작성 기록만 있음 → 수용률 "AI 초안 기록 없음"(0%로 보이면 안 됨)
- 화면을 오래 열어 둔 기록(수 시간) → 평균을 망치지 않음(30분 초과 제외, 건수 표시)
- 설정 파일 오타(없는 기관 이름, 중복 이메일·식별번호, 형식이 틀린 식별번호) → 아무것도 만들기 전에 전부 알려 줌
- 스크립트를 두 번 실행 → 계정·대상자가 중복되지 않고 비밀번호도 바뀌지 않음

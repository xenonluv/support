# 파일럿 연습 데이터 실행 계획

## Context
- 운영 사이트의 파일럿 대상자(C-2001~2020, 앱에서 등록한 대상자 포함)에는 기록·신호가 없다.
  - 그래서 현장 [상황 보기], 이상징후 현황, 브리핑이 빈 화면이라 교육·시연이 안 된다.
- 사용자 결정: 모든 대상자의 현장 기록을 무작위로 자세히 채운다. 이후 실제 데이터는 현장 기록으로 쌓는다.

## 지켜야 할 것
1. **실제 운영 전에 반드시 지운다.**
   - 번호는 종이 대응표로 실제 어르신과 연결된다.
   - 가짜 '낙상·약 미복용'이 남으면 실제 상태로 오해해 돌봄 판단이 틀어진다.
2. **성과지표에서 뺀다.**
   - `stt_engine = 'pilot-demo'` 표시를 붙이고, 지표는 `DEMO_ENGINES`(seed-demo, pilot-demo)를 뺀다.

## 작업
- `src/lib/pilot/demo-plan.ts`: 순수 함수 `planPilotDemo({ clients, workers, managerId, now, seed })`
  - 대상자마다 인물 유형(고혈압·당뇨, 무릎 관절염, 경도 인지저하 등 10가지)을 정해, 그에 맞는 기록 3~7건을 최근 3주에 배치한다.
  - 기관 종류에 맞는 서비스를 쓴다: 동 센터는 상담·연계, 수행기관은 생활지원, 복지관은 프로그램·도시락.
  - 신호 장면은 11가지다.
    - 해소 안 된 것 7가지: 미확인·확인함·조치 중, 두 기관에서 함께 관찰한 경우 포함
    - 해소된 것 4가지: 연계 후 해소 포함
  - 주의 등급에는 동 담당자 알림 문안을 붙인다.
  - 연령대가 비어 있으면 인물 유형에 맞게 채운다.
  - 같은 seed면 같은 결과가 나온다.
- `scripts/pilot-demo.mts` (`npm run pilot:demo`)
  - 대상: 파일럿 참여자(현장) 기관과 연결된, 종결 안 된 대상자. 작성자는 각 대상자와 연결된 기관의 파일럿 현장 인력이다.
  - 다시 실행하면 이전 연습 데이터를 지우고 새로 넣는다.
  - 채운 연령대와 채운 시각을 `pilot/pilot-demo-state.json`(git 제외)에 남긴다.
  - `--clear`
    - 연습 기록·신호·알림 문안을 지운다.
    - 채운 뒤 만든 브리핑을 지운다.
    - 우리가 채운 연령대는 값이 그대로일 때만 비운다.
- 테스트(`tests/pilot/demo-plan.test.ts`)
  - 모든 기록이 기록 서식에 맞는지
  - 작성자가 연결 기관의 현장 인력인지
  - 날짜가 과거 3주 안인지
  - 신호와 알림 문안이 규칙에 맞는지
  - 같은 seed면 같은 결과인지
  - 개인정보 마스킹에 걸리는 글이 없는지
- 문서: `doc/파일럿운영.md`에 실행·삭제 순서를 적는다. 실제 운영 전에 `--clear`를 반드시 실행한다.

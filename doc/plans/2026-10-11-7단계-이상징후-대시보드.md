# 7단계 기능③ 이상징후·대시보드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** 기록 초안을 만들 때 같은 Claude 호출로 이상징후 5종(근거 문장 포함)과 알림 문안을 함께 받는다. 현장 인력이 확인해 저장하면 관리자 대시보드가 실제 DB로 "먼저 확인할 어르신"을 보여 주고, 알림 문안 복사와 신호 상태 변경을 처리한다.

**Spec:** `doc/단계개발.md` 5장 "7단계", `doc/구현1.md` 3장 기능③·7-2장, 시안 `doc/design_ui.png`

## 결정 (2026-10-11)
- 신호는 5종만 쓴다: `missed_medication` 약 미복용, `reduced_meal` 식사량 감소, `fall` 낙상(휘청 포함), `emotional_withdrawal` 정서적 위축, `visit_refusal` 방문 거부·연락 두절. 시안의 주거·경제는 제외한다.
- 수준은 관찰/주의다. "판정"이 아니라 **확인 우선순위 제안**이고, 화면 문구도 그렇게 쓴다.
- "이번 달 조기 발견" = 이번 달(서울 기준)에 `outcome='linked'`로 해소 처리된 신호 수
- 근거 문장은 가린 구술 글 안에 실제로 있어야 한다(띄어쓰기 무시 비교). 없으면 그 신호는 버린다. 지어낸 근거를 막기 위해서다.
- 알림 문안은 신호가 있을 때만 하나 만든다. 동 담당자용이고 성명 없이 식별번호만 쓴다. 저장할 때 우선순위가 가장 높은 신호에 붙인다(`alert_drafts.flag_id`).
- 집계는 읽을 때 계산한다(순수 함수 `buildDashboard`, TDD).
  - 대상자·신호 종류별로 해소되지 않은 플래그를 묶는다.
  - 지속 일수 = 오늘 − 가장 이른 발견일 + 1
  - 신규 = 48시간 안에 처음 발견
  - 관찰 기관 수 = 그 신호들이 나온 기록의 기관 수
  - 정렬: 신호 수 → 최장 지속 → 관찰 기관 수
  - 상태: 주의 있음 → 주의, 관찰만 → 관찰, 기간 안에 해소만 → 해소
  - 요약 카드: 주의 필요·관찰 지속 대상자 수, 특이사항 없음 = 전체 − 둘, 이번 달 조기 발견. 추이는 최근 10일 일별 값.
  - 기간 필터: 7·14·30일(기본 14). 기간 안에 발견된 플래그와 기록만 센다.
- 상태 변경(관리자만, RLS): 대상자·신호 종류 단위로 확인/조치 중/해소를 바꾼다. 해소 때 "연계로 이어짐"을 선택할 수 있다.
- 알림 문안 [복사] → `copied_at` 기록
- 관리자 화면의 예시 데이터와 미리보기 띠를 없앤다. 사이드바 숫자도 실제 값으로 바꾼다.
- 중간발표용 시연 데이터: `npm run seed:demo`
  - 시험 대상자에게 여러 날짜의 기록·신호를 넣는다(멱등, `stt_engine='seed-demo'`로 구분해 다시 넣음).
- 탐지 점검: 운영 서버에서 샘플 구술 15건을 실제 초안 API로 보내 기대 신호와 비교하고, 오탐·누락을 문서에 기록한다.

## Tasks
1. 스키마·프롬프트
   - `SignalSchema`, `DraftOutputSchema`(기록+신호+알림)
   - `generateDraft`가 신호·알림을 돌려주게 하고, 근거 검증 `keepGroundedSignals`를 TDD로 만든다.
2. 저장: `SaveRecordSchema`에 signals·alertDraft 추가, `buildFlagRows` TDD, `saveRecord`가 flags·alert_drafts도 넣게 한다.
3. 현장 화면: 초안 아래 "확인이 필요한 신호" 카드(근거 인용). 저장 전에 빼거나 둘 수 있게 한다.
4. 집계 `buildDashboard` TDD → 관리자 데이터 조회 → `/signals`(카드·목록·기간 필터), `/signals/[code]`(상세·문안·상태 변경), 서버 액션 2개, 사이드바 실제 숫자, 예시 데이터 삭제
5. 시연 데이터 스크립트, 운영 탐지 점검 스크립트
6. 검증
   - typecheck·lint·test·build, RLS(관리자 상태 변경, 현장 상태 변경 거부 추가)
   - 로컬 크롬: 관리자 대시보드 숫자가 DB와 일치하는지, 상태 변경·복사 기록
   - 운영: 실제 탐지 점검

# 6단계 기능① 음성 → 기록 초안 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** 현장 인력이 대상자를 고르고 녹음(또는 글 입력)하면 Groq가 글자로 바꾼다. 개인정보를 가린 뒤 Claude가 기록 초안(JSON)을 만들고, 사람이 고쳐 저장·복사한다. 수용률·작성시간 측정값(`edited`, `edit_ratio`, `duration_ms`)도 함께 저장한다.

**Spec:** `doc/단계개발.md` 5장 "6단계", `doc/구현1.md` 3장(기능 ①)·5장(처리 흐름)·8장(프롬프트)·9장(개인정보)

## 설계 결정
- **기록 서식**: 「2026년 노인맞춤돌봄서비스 사업안내」 원문이 아직 없으므로 임시 항목으로 시작한다. 원문을 받으면 `src/schemas/record-draft.ts` 한 곳만 바꾼다.
  - 요약
  - 서비스 유형: 안전지원·사회참여·생활교육·일상생활지원·연계서비스
  - 건강·복약·식사·정서·생활환경
  - 제공 서비스, 특이사항, 후속 조치
  - 구술에 없는 항목은 빈 문자열로 둔다(지어내지 않음).
- **모델**: `claude-sonnet-5-5`(확정 결정). `CLAUDE_DRAFT_MODEL` 환경변수로 바꿀 수 있고, 모델명은 `src/lib/ai/models.ts` 한 곳에서만 관리한다.
  - 구조화 출력: `messages.parse` + `zodOutputFormat`(Zod 스키마 그대로 사용)
  - effort `low`(추출 작업): 지연·비용 절감
  - 시스템 프롬프트에 캐시 지정
- **거절(refusal)**: Sonnet 5.5의 서버 측 대체 모델은 보안·AI개발 분야 거절만 다시 시도하므로 돌봄 기록에는 의미가 없어 쓰지 않는다. 거절되면 "직접 입력" 안내를 보여 준다.
- **응답 방식**: 스트리밍 없이 한 번에 받는다(3~5초 목표). 실측 후 필요하면 스트리밍으로 바꾼다.
- **개인정보 가림** `src/lib/privacy/mask.ts`
  - 대상: 전화번호, 주민번호, 이메일, 도로명·지번·동호수 주소, "성+이름 + 어르신/할머니/할아버지/씨/님"
  - '오늘 어르신' 같은 일반 낱말은 예외 목록으로 거른다.
  - LLM 호출 전과 DB 저장 전에 모두 거친다(여러 번 거쳐도 결과가 같음).
- **저장**: 서버 액션 `saveRecord`
  - Zod로 검사하고 다시 가린다.
  - 내 기관(`workers.agency_id`)과 대상자(식별번호 → id)를 찾아 RLS 아래에서 insert 한다.
  - `edit_ratio` = 초안 글과 최종 글의 편집 거리 비율(0~1)
- **화면**
  - `/visits`: 내 기관과 연결된 실제 대상자 목록과 마지막 기록일
  - `/record?client=코드`: 대상자 선택 → 녹음(4단계 `useRecorder` 재사용) 또는 글 입력 → 글자 확인·수정 → [초안 만들기] → 항목별 수정 → [저장]·[복사]
  - `/my-records`: 내가 저장한 최근 기록과 [복사]
  - 현장 화면은 실제 데이터가 되므로 "미리보기" 띠를 없앤다(관리자 화면은 7단계까지 유지).
- **실제 Claude 호출 확인**: 운영 키가 민감 정보라 로컬에서는 받을 수 없다. 단위 테스트는 가짜 응답(fixture)으로 하고, 실제 호출은 배포 후 운영 서버에서 확인한다(4단계 STT와 같은 방식).

## Tasks
1. 순수 로직 TDD
   - `maskPersonalInfo`
   - `RecordDraftSchema`·요청 스키마
   - `formatRecordText`(복사용 글)
   - `editRatio`
   - `buildRecordRow`(저장 행 만들기)
2. `src/lib/ai`(models·prompt·`generateDraft`), 가짜 클라이언트로 TDD(정상·거절·파싱 실패)
3. `POST /api/draft`(같은 사이트·로그인·입력 검사·가림·생성), 라우트 테스트
4. 서버 액션 `saveRecord`, 내 대상자·내 기록 조회 함수
5. 화면(`/visits`, `/record`, `/my-records`), 현장 미리보기 띠 제거
6. 검증
   - typecheck·lint·test·build, RLS 재검사
   - 로컬 크롬: 글 입력 → 초안 버튼까지(키 없음 안내 확인)
   - 배포 후: 운영 서버에서 실제 Claude 초안·저장·복사, 지연 실측

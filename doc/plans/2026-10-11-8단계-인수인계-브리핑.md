# 8단계 기능② 인수인계 브리핑 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** 관리자가 대상자와 기간(기본 2주)을 고르면, 여러 기관의 방문 기록을 시간순으로 모아 Claude가 "그동안 이 어르신에게 무슨 일이 있었는가"를 한 장으로 요약한다. 미해결 이상징후와 함께 보여 주고 [복사]할 수 있다.

**Spec:** `doc/단계개발.md` 5장 "8단계", `doc/구현1.md` 3장 기능②, 시안 `doc/design_ui.png`(대시보드 행의 [브리핑] 버튼)

## 결정 (2026-10-11)
- 화면은 관리자 전용이다(`/briefing`, `/briefing/[식별번호]`). 주소 분기(`MANAGER_ONLY`)와 서버 액션의 역할 확인으로 막는다.
  - DB 권한(RLS)은 5단계 그대로 둔다: 볼 수 있는 대상자의 브리핑만 읽고, 본인 이름으로만 저장한다.
- 생성은 `/api/briefing` 대신 **서버 액션** `createBriefing`으로 한다.
  - 결과를 `briefings`에 저장하고 화면을 새로 그려 보여 준다(7단계 상태 변경과 같은 방식).
  - 초안과 달리 브라우저에서 고칠 상태가 없어서 이쪽이 단순하다.
- 비용: 화면을 열 때마다 자동으로 만들지 않는다. [브리핑 만들기]를 눌렀을 때만 Claude를 부른다.
  - 같은 기간(시작일·종료일 일치)의 가장 최근 브리핑을 다시 보여 준다.
  - 만든 뒤 새 기록이 들어왔으면 "새 기록 N건 — 다시 만들기"를 안내한다.
- 기간: 7·14·30일(기본 14). 서울 기준으로 오늘 포함 N일, 시작일 0시부터의 `visited_at`
- Claude 입력 (`<대상자>`, `<기간>`, `<기록>`, `<미해결 신호>`)
  - `<기록>`: 시간순, 각 기록 앞에 "[10월 3일 · 기관 이름]"을 붙인다. `final_json`에서 비어 있지 않은 항목만 넣는다.
  - 기록이 20건을 넘으면 요약·특이사항·후속 조치만 넣는다(토큰 절약). 최대 60건, 최신 기록 우선.
  - 입력 전체를 마스킹한다. 구술 원문(`transcript_text`)은 넣지 않는다.
- 출력(Zod 구조화 출력, `schemas/briefing.ts`)
  - `overview`: 2~3문장
  - `changes`: 날짜 붙은 변화, 6개 이하
  - `by_agency`: 기관마다 {agency, summary}
  - `follow_ups`: 이어서 확인할 일, 5개 이하
  - 개수 상한은 받은 뒤 자른다(구조화 출력 스키마에 개수 제약을 넣지 않는다).
  - 받은 글은 다시 마스킹한다. `by_agency`는 입력에 있던 기관 이름만 남기고, 입력 순서대로 정렬한다.
- 미해결 이상징후는 AI 요약과 별개로 DB에서 바로 보여 준다(7단계 `buildDashboard` 재사용). 상태를 바꾸는 링크도 단다.
- 저장: `briefings.body`에 JSON 문자열로 넣는다. 읽을 때 Zod로 검사하고, 깨졌으면 글 그대로 보여 준다.
- AI 공통 부분(클라이언트 형식, 오류 클래스, 기본 클라이언트)을 `lib/ai/client.ts`로 옮겨 초안·브리핑이 함께 쓴다.
- 모델: `BRIEFING_MODEL` = `CLAUDE_BRIEFING_MODEL` 또는 `claude-sonnet-5-5`, effort low
- 대시보드 행의 [브리핑] 버튼, 사이드바 "인수인계 브리핑"을 연결한다.
- 시연 데이터: C-0012의 두 기관 기록 내용을 서로 다르게 채운다(A: 복약·휘청, B: 목욕·병원 동행). 완료 기준 확인에 쓴다.

## Tasks
1. AI 공통 모듈 분리(`lib/ai/client.ts`), 기존 초안 테스트 그대로 통과
2. 순수 함수 TDD
   - `lib/briefing/period.ts`: `briefingPeriod(now, days)` → {from, to, startIso, label}
   - `lib/briefing/input.ts`: `buildBriefingInput(...)` → {text, agencies}(시간순·기관 표시·빈 항목 제외·축약·마스킹·신호 줄)
   - `schemas/briefing.ts`: 출력 스키마, 요청 스키마, `parseBriefingBody`
   - `lib/briefing/format.ts`: 복사용 글 `formatBriefingText`
3. `lib/ai/briefing.ts` `generateBriefing` TDD(가짜 클라이언트): 캐시된 시스템 프롬프트, 출력 마스킹·기관 필터·개수 자르기, 거절·실패·키 없음
4. 데이터·액션
   - `lib/briefing/data.ts`: 목록·화면 데이터, 생성용 원자료 조회
   - `lib/briefing/actions.ts` `createBriefing` TDD(모듈 가짜): 입력 검사, 관리자만, 대상자 없음, 기록 없음(Claude 안 부름), 저장, 새로 그리기
   - `getAuthSession()`(id·역할)을 `lib/auth/session.ts`에 추가
5. 화면
   - `/briefing`: 대상자 목록(최근 2주 기록 수·기관 수)
   - `/briefing/[code]`: 기간 선택, 기록·기관 현황, 미해결 신호, AI 브리핑(만들기·다시 만들기·복사)
   - 대시보드 [브리핑] 링크, 사이드바 메뉴, 관리자 전용 주소
6. 시연 데이터 보강, RLS 검사 추가(브리핑 저장·조회 범위)
7. 검증
   - typecheck·lint·test·build, `npm run test:rls`
   - 로컬 크롬: 목록·화면·기간·미해결 신호·저장된 브리핑 표시·복사·오류 안내·현장 계정 차단, 회귀
   - 운영(배포 후): C-0012 브리핑에 두 기관 내용이 모두 들어가는지, 이름·전화번호가 남지 않는지

## Review Focus
- 기간 안에 기록이 0건 → Claude를 부르지 않고 "기록이 없어 만들 수 없어요"
- 서울 새벽(UTC 전날) → 기간 시작·끝 날짜가 서울 기준이어야 함
- 기록 수정본(`final_json`)에 사람이 이름·전화번호를 적은 경우 → 입력 마스킹으로 가림
- Claude가 입력에 없는 기관 이름을 지어냄 → 버림
- 만들기를 두 번 연달아 누름 → 진행 중에는 버튼을 막음

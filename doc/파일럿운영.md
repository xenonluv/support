# 파일럿 운영 절차 (9단계)

현장 파일럿(5~10명, 2주)을 준비하고 운영하고 마무리하는 순서다. 명령은 모두 `web/`에서 실행한다.

## 1. 준비 — 참여자 정보 받기
- 기관: 이름, 종류
  - 종류는 `dong_center`(동 행정복지센터), `provider`(수행기관), `welfare_center`(복지관) 중 하나
- 대상자: **식별번호(C-숫자4자리)·연령대(10단위)·동**과 담당 기관
  - 성명·주소·연락처는 받지 않는다. 다른 칸이 있으면 스크립트가 거부한다.
- 참여자: 이메일, 화면에 보일 이름, 역할(`worker` 현장 / `manager` 동 담당자), 소속 기관
- 기존 작성시간: 사전 수요조사에서 기록 1건을 쓰는 데 걸린 시간(분). 작성시간 단축률 계산에 쓴다.

`web/pilot/pilot.example.json`을 `web/pilot/pilot.json`으로 복사해 채운다.
- 이 폴더의 다른 파일은 git에 올라가지 않는다(참여자 이메일·임시 비밀번호).
- 시험용 기관("화정1동 행정복지센터", "서구 노인맞춤돌봄 수행기관")과 이름이 같으면 시험 데이터와 섞인다. 실제 기관 이름이 같다면 먼저 알려 달라(시험 데이터 정리 후 진행).

## 2. 계정 발급
```bash
npm run pilot:accounts -- pilot/pilot.json
```
- 틀린 곳이 있으면 아무것도 만들지 않고 목록을 보여 준다. 고쳐서 다시 실행한다.
- 성공하면 `web/pilot/accounts-<서울시각>.csv`에 임시 비밀번호가 생긴다.
  - 개인 메시지로 한 명씩 전달하고, 전달이 끝나면 파일을 지운다.
- 다시 실행해도 계정이 중복되지 않고 비밀번호도 그대로다. 비밀번호를 새로 만들려면 `-- pilot/pilot.json --reset-passwords`
- 발급된 계정은 "파일럿 참여자"로 표시되고, 성과지표는 이 사람들의 기록만 센다. 시험 계정과 시연 데이터는 빠진다.

**발급 현황 (2026-10-11, 임시 구성)**
- 실제 참여자 정보 없이 자리만 만들어 두었다. 실제 사람에게 계정을 하나씩 나눠 주는 방식이다.
- 기관 3곳: ○○동 행정복지센터, ○○구 노인맞춤돌봄 수행기관, ○○종합사회복지관
- 대상자 20명: C-2001~C-2020, 연령대 비움, 동 "○○동"
  - 모두 동 센터에 연결한다.
  - C-2001~2012는 수행기관, C-2009~2020은 복지관에 연결한다. C-2009~2012는 두 기관이 함께 맡는 브리핑 대상이다.
  - 실제 사람과 식별번호의 대응표는 기관이 종이로 따로 보관한다.
- 계정 9개: pilot01@dolbomieum.kr(동 담당자, 관리자), pilot02~03(동 통합돌봄), pilot04~07(생활지원사), pilot08~09(사회복지사)
- 실제 기관명·이름·연령대가 정해지면 `pilot/pilot.json`을 고쳐 다시 실행한다. 이름은 그대로 바뀐다.
  - 기관명을 바꾸면 새 기관이 생긴다. 그래서 기관명은 DB에서 직접 고친다.
- 이 계정으로는 연습 기록을 남기지 않는다. 남기면 성과지표에 들어간다. 연습은 시험 계정이나 마이크 테스트 화면에서 한다.

## 3. 참여자 안내
- 사용 안내: https://dolbomieum.kr/guide
  - 로그인 없이 볼 수 있다. 인쇄하면 A4 한 장이다.
  - 다루는 내용: 접속, 홈 화면 추가, 마이크 허용, 말하는 요령, 신호 빼기, 잘 안 될 때
- 첫날 함께 확인할 것: 로그인, 마이크 허용, 시험 녹음 1건(마이크 테스트 화면)

## 4. 운영 중 (2주)
- 동 담당자(관리자 계정)는 `성과 지표` 메뉴에서 자기 기관 참여자의 지표를 본다.
- 매주 한 번 백업한다: `npm run backup`
  - 결과는 `web/backups/`에 쌓이고, 돌봄 기록이 들어 있으니 이 컴퓨터 밖으로 옮길 때는 암호화한다.
  - 무료 요금제는 자동 백업이 없다.
- Supabase에서 "일시정지 예정" 메일이 오면 알려 달라.
  - 하루 한 번 자동으로 깨우지만, 메일이 오면 확인이 필요하다.

## 5. 마무리 — 최종 지표
```bash
npm run metrics -- --baseline=기존작성시간(분)
```
- 모든 기관 파일럿 참여자 기준으로 성과지표 4개와 달성 여부(✓/✗)를 출력한다.
  - 작성시간 50% 단축, 5~10명·2주, 누적 200건, 수용률 80%
- 수용률 기준
  - AI 초안 기록 중 그대로 저장했거나 글자 20% 이하로 고친 비율
  - 'AI 없이 직접 작성'한 기록은 뺀다.
- 작성시간 기준: 녹음·입력 시작부터 저장까지의 평균. 30분을 넘긴 기록은 화면을 열어 둔 것으로 보고 뺀다.

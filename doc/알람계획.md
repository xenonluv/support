# 관리자 → 현장인력 웹푸시 알림 계획 (간단 버전)

> 2026-10-20 작성, 같은 날 간단 버전으로 고침. 한 기관의 의뢰("관리자가 현장인력에게 웹푸시 알림을 띄울 수 있는가")에 대한 검토와 구현 계획.
> 처음 안(수락/불가 응답, 10분 미확인 시 전화 표시, 등급 3단계, 대체 방문 배정, 기록 누락 자동 알림)은 파일럿 1차에서 뺐다. 기록과 신호가 이미 앱에 다 있으므로, 알림은 "들어와서 보세요"라는 신호만 보내면 된다.

## 답변 요약
- **됩니다.** 지금의 돌봄이음 웹 서비스에 기능을 더합니다. 발송 비용은 없습니다(문자 요금 없음).
- **관리자가 위험 신호가 있는 대상자 화면에서 버튼 하나로 보냅니다.** 그 대상자를 함께 돌보는 모든 기관의 현장인력이 받습니다.
- **브라우저를 닫아도 휴대폰에 옵니다.** 안드로이드는 크롬·삼성 인터넷, 아이폰은 홈 화면에 추가한 앱에서 됩니다.
- **긴급 연락 수단은 아닙니다.** 도착이 보장되지 않고 무음 모드를 뚫지 못합니다. 응급 상황은 지금처럼 119와 전화가 먼저입니다.
- **AI가 찾은 신호를 자동으로 보내지 않습니다.** 관리자가 확인하고 누릅니다. 잘못된 알림이 쌓이면 현장에서 알림을 꺼 버립니다.

## 흐름
1. 현장인력이 처음 한 번 "오늘의 방문" 화면에서 **[알림 받기]**를 켭니다. **[테스트 알림]**으로 자기 휴대폰에 오는지 확인합니다.
2. 관리자가 이상징후 상세 화면(`/signals/[식별번호]`)에서 **[현장 인력에게 알림]**을 누릅니다.
3. 그 대상자와 연결된 모든 기관의 현장인력 기기로 알림이 갑니다.
   - 문구: "확인이 필요한 대상자가 있습니다. 눌러서 확인해 주세요."
   - 잠금 화면에 보이므로 이름·식별번호·건강 정보는 넣지 않습니다.
4. 알림을 누르면 대상자 상황 화면(`/visits/[대상자]`)이 열립니다. 위험 신호와 모든 기관의 기록이 이미 거기 있습니다.
   - 로그인이 풀려 있으면 로그인한 뒤 그 화면으로 돌아갑니다.
5. 관리자 화면에는 "○명(기기 ○대)에게 보냄"과 최근 보낸 시각이 남습니다.

## 받는 사람 범위
- **그 대상자와 연결된 모든 기관의 현장인력**(역할 `worker`)입니다.
- 현장인력은 이미 연결된 대상자의 기록과 신호를 기관에 상관없이 읽습니다(RLS `can_see_client`). 알림도 같은 범위로 보내므로 새로 넓어지는 권한이 없습니다.
- 관리자도 그 대상자를 볼 수 있는 사람만 보낼 수 있습니다.

## 기기별 지원
| 환경 | 받음 | 비고 |
|---|---|---|
| 안드로이드 크롬·삼성 인터넷 | 됨 (브라우저 닫아도) | 알림 허용 1회. 설정에서 앱을 강제 종료하면 다시 열 때까지 안 옴 |
| 아이폰 (iOS 16.4 이상, 홈 화면에 추가한 앱) | 됨 (앱 닫아도) | 홈 화면 앱 안에서 [알림 받기]를 눌러야 함 |
| 아이폰 사파리 (홈 화면 추가 안 함) | 안 됨 | 화면에 홈 화면 추가 안내 |
| 카카오톡 등 앱 안의 브라우저 | 안 됨 | 크롬·사파리로 열도록 안내 |

## 한계 (기관에 미리 설명)
1. 도착이 보장되지 않습니다. 전화기가 꺼져 있으면 하루 안에 켜질 때 도착하고, 절전·방해금지 모드에서는 늦거나 소리 없이 옵니다.
2. 무음 모드를 뚫지 못합니다.
3. 읽었는지는 알 수 없습니다(1차에서는 확인 버튼이 없습니다). 꼭 전달해야 하면 전화합니다.

## 설계
### DB (마이그레이션 1개)
- `push_subscriptions`: 알림 받을 기기. 한 사람이 여러 기기를 가질 수 있습니다.
  - `id`, `worker_id`, `endpoint`(unique), `p256dh`, `auth`, `created_at`
  - 본인 것만 조회·삭제. 저장은 함수 `save_push_subscription`으로 합니다(같은 기기를 다른 계정이 쓰던 경우 주인을 바꿈).
- `push_alerts`: 보낸 기록. `id`, `client_id`, `sender_id`, `recipient_count`, `device_count`, `delivered_count`, `created_at`
  - 그 대상자를 볼 수 있는 관리자만 조회합니다.
- 함수 `send_client_alert(대상자)`: 관리자이고 그 대상자를 볼 수 있을 때만 됩니다. 보낸 기록을 만들고 받을 기기 목록을 돌려줍니다. 같은 대상자로 1분 안에 다시 보내면 거절합니다(중복 누름 방지).
- 함수 `finish_client_alert(보낸 기록, 도착 수, 만료 기기)`: 보낸 사람만 부릅니다. 도착 수를 적고 만료된 기기(404/410)를 지웁니다.
- 비밀 키(`SUPABASE_SECRET_KEY`)는 쓰지 않습니다. 권한 판단은 DB 함수 안에서 합니다.

### 서버
- 라이브러리 `web-push`(VAPID). 환경변수 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
  - 공개키는 서버 화면에서 버튼으로 넘깁니다. `NEXT_PUBLIC_` 접두사를 쓰지 않습니다.
- 푸시 내용에는 고정 문구와 열 주소(`/visits/<내부 id>`)만 넣습니다. 테스트로 확인합니다.
- 보관 기간(TTL) 1일, Urgency `high`.

### 화면
- 현장인력 "오늘의 방문" 위: [알림 받기] / 켜짐 상태와 [테스트 알림] / 지원 안 되는 환경 안내.
- 관리자 `/signals/[식별번호]`: [현장 인력에게 알림] 버튼(확인 창 → 결과 문구), 최근 보낸 시각.
- `public/sw.js`: 알림 표시, 누르면 해당 화면 열기.
- 로그인 화면은 `next` 주소를 받아 로그인 뒤 돌아갑니다(역할에 맞는 내부 주소만).

## 나중에 (기관 요청이 있을 때)
- 수락/불가 응답과 미확인 시 전화 표시, 대체 방문 배정
- 동 단위 일괄 안부 확인(폭염·한파)
- 기록 누락 알림: 방문 일정 데이터가 없어 지금은 판단할 수 없습니다.

## 기관에 확인할 것
1. 현장인력 기기 현황(아이폰 비율, iOS 16.4 이상인지)
2. 근무시간 외(야간·주말) 발송 여부
3. 알림을 받은 뒤 누가 무엇을 하는지(방문 앞당기기, 전화 확인 등) 기관 안의 약속
